# 범용 편도 안내 구현 및 검증

## 구현 범위

로그인 없는 시작 → 동의 → 접근성 설정 → 코레일+ 열기 또는 연습.
마이크는 사용자가 누를 때만 요청하고 글자 입력을 항상 제공한다.
출발역·도착역·날짜·조회 시작 시각·승객 유형과 인원을 한 번에 또는 나눠 입력한다.
누락 조건을 질문하고 사용자가 최종 확인한 뒤 안내한다.
홈에서 새 조건 입력을 시작하면 이전 여행 조건을 비우며, 안내 중 조건 수정은 기존 조건을 유지한다.
성인·어린이·유아·경로 인원 합계 1~9명, 정시 단위 조회를 지원한다.
왕복·환승·할인상품은 이번 범위에서 제외한다.

역 검색어만 자동 입력한다. 역 선택, 달력, 인원, 조회, 열차·호차·좌석은 사용자가 직접 누른다.
로그인·인증·개인정보·최종 확인·결제 화면에서는 안전 안내 후 중단한다.
원본 음성 및 원본 화면 텍스트는 저장하지 않는다.

## 실제 기기 확인

2026-10-03, Galaxy Note9 SM-N960N / Android 10 / 코레일+ 7.0.4.
부산 → 대전, 2026-10-04 15시 이후, 성인 2명·어린이 1명으로
역 검색·날짜·시간·인원 설정을 거쳐 실제 열차 조회 결과에 도달했다.
열차 선택·예약·결제는 수행하지 않았다.

실제 Compose 화면에서 발견한 문제를 수정했다:

- 인원 홈은 유형별 인원이 아니라 합계만 노출하므로 인원 선택창에서 유형별 값을 먼저 검증한다.
- 날짜 선택창의 시간 요약 `15시 이후`를 선택 상태로 인식한다.
- 서비스 이벤트가 누락되는 복귀 상황에 짧은 재확인 경로를 둔다.
- 조건 입력 Activity에서는 코레일용 말풍선을 숨긴다.
- 하단 선택 완료 버튼을 안내창이 가리지 않도록 위치를 조정한다.
- 조회 옵션창을 좌석 선택 화면으로 잘못 분류하지 않는다.
- `인접역 포함`은 메뉴 이름이며 실제 포함 여부는 설정을 직접 확인한다.

## 재현 검사

```sh
JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home ./gradlew testDebugUnitTest lintDebug assembleDebug mock-korail:assembleDebug
```

단위 테스트는 누락 질문, 조건 수정, 여러 출도착역, `까지`·`역으로` 및 역명 뒤 출발/도착 표기,
`어른 두 분`처럼 단위 명사가 빠진 수 표현, 유형별 인원,
정시 아닌 시각 거부, 역 이름 정확한 일치, 날짜·시간·인원 상태 검증,
기존 결과 재사용 방지, 옵션창 구분, 경유 요청과 지원·미지원 좌석 조건이 섞였을 때
전체 조건을 보류하는 회귀 검사를 포함한다. 왕복·환승의 구어체 표현과 대표 할인상품명도
조건 일부를 적용하지 않고 요청 전체를 보류하는지 확인한다. 이해하지 못한 조건이 완성된 노선·날짜·인원과
같이 들어와도 그 조건을 조용히 버리지 않고 요청 전체를 보류하는지 검사한다. 결과 화면에서는 접근성 정보가 출발 시각임을
명시할 때만 요청 시각과 비교하고, 구분할 수 없는 시각은 사용자에게 직접 확인하도록 한다.
자정을 넘는 도착 시각이 출발 시각 검사에 섞이지 않는지도 검사한다.
상품명 예시는 코레일의 [승차권 FAQ](https://info.korail.com/info/selectBbsNttList.do?bbsNo=205&key=817&pageIndex=11&searchCnd=all)와
[2026년 할인제도 안내](https://info.korail.com/info/selectBbsNttView.do?bbsNo=199&key=911&nttNo=26335&pageIndex=8&searchCnd=all)에서 확인했다.
키워드는 대표 사례일 뿐 할인상품 전체 목록이 아니므로, 공식 명칭이 바뀌거나 추가되면 갱신해야 한다.

추가 회귀 검사는 역순 조회 결과와 열차 행의 좌석 수를 요청 조건으로 오인하지 않는지,
매진·예약대기·일시 오류에서 잘못된 버튼을 안내하지 않는지,
좌석 화면에서 하단 완료 버튼을 가리지 않도록 안내창을 위로 옮기는지 확인한다.
입력 화면 회전 복원용 초안은 구조화된 조건만 저장 상태에 담으며 발화 원문은 제외한다.
이 초안 복원은 단위 테스트했지만, 코레일 앱으로 넘어가는 도중 프로세스가 종료된 경우의
요청 복구는 아직 기기에서 검증하지 않았다.

2026-10-03 검증에서 단위 테스트 109개, 실패 0. `lintDebug`, `assembleDebug`,
`mock-korail:assembleDebug` 통과.

전용 Android 35 AVD의 `mock-korail`에서 두 편도 요청을 조회 결과까지 재현했다:

- 진주→서울, 다음 날 06시 이후, 어른 2명·어린이 1명
- 부산→대전, 다음 날 09시 이후, 어른 2명·어린이 1명

첫 요청 결과에는 노선·날짜와 열차 목록만 표시되고 시간·인원 요약은 없었다.
앞 단계에서 확인한 날짜·시간·유형별 인원을 기준으로 안내하고, 요청 시각보다 이른
열차는 결과 안내에서 제외한다. 두 번째 요청은 안전 가드가 있는 AVD 전용 실행기로
재현했으며, 노선·날짜와 09:00 이후의 매진/예매 가능 예시를 확인했다. 두 경우 모두
열차·좌석·예매·결제는 누르지 않았다. `mock-korail` 결과이므로 실제 코레일 서버 응답,
좌석 가용성 또는 전국 노선에서의 완전성을 증명하지 않는다.

후속 회귀 테스트는 매진 항목만 보일 때는 진행을 막고, 매진과 함께 직접 예매 가능한
버튼이 보이면 사용자가 고를 수 있도록 안내하는 두 경우를 단위 테스트한다.
접근성 타깃의 경계 중앙을 사용하는 최신 2시나리오 AVD 실행기는 승객 수 조정 단계에서
간헐적으로 진행하지 못해 아직 통과로 기록하지 않는다. 이를 안정화한 뒤 결과 게이트까지
다시 확인해야 한다.

AVD에서 마이크 권한을 거부한 뒤에도 글자 입력을 사용할 수 있다는 안내와 텍스트 입력란을
확인했다. 앱 시작 시 권한 팝업은 없고 마이크 버튼을 누를 때만 Android 권한창을 요청했다.
접근성 서비스 설정에서 제스처 기능은 제거했고, AVD의 바인딩된 서비스 capability는
spoken feedback만 표시했다. 글자 입력 동작과 권한 거부 후 UI는 AVD에서 확인했지만,
실사용 음성 인식 품질은 검증하지 않았다.

`scripts/run_android_demo_e2e.py`는 emulator serial과 QEMU/mock 패키지를 검사하고,
조회 결과 화면에서 종료하도록 제한했다. 실기기 serial은 초기에 거부되며 코레일 앱의
초기화·강제 종료·권한 변경, 열차 선택 또는 예약 동작을 수행하지 않는다.

이번 검증에서 최신 디버그 APK를 설치한 대상은 전용 AVD다. SM-N960N은 이번 ADB 세션에
연결되지 않아 최신 APK의 실기기 재검증은 하지 않았다. 위의 별도 실기기 기록은 유지한다.

## 아직 확인해야 하는 범위

사용자 실제 발화에 대한 음성 인식, 마이크가 허용된 경우의 인식 품질,
원하는 열차를 사용자가 선택한 뒤 실제 호차·좌석 화면의 상단 안내,
매진·오류 복귀 및 다른 역·날짜의 최신 실기기 재검증은 별도 확인이 필요하다.
현재 결과만으로 모든 코레일 화면 또는 모든 예약 상황의 무중단 동작을 보장하지 않는다.
열차 결과에서는 임의로 열차를 추천하거나 자동 선택하지 않고 화면의 선택지를 직접 고르게 한다.
민감 화면에 진입하면 안내를 중단하므로 예매·결제 완료까지 자동 진행하는 제품이 아니다.
